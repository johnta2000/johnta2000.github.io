# Site access overview

`/tools/access/` is a read-only owner overview. The `accessOverview:verify` and `accessOverview:overview` queries require either `johnta2018@gmail.com` or `john@affil.ai`. Explicit failed email verification is rejected. An omitted claim is accepted only from the pinned site's Clerk issuer, consistent with the other private tools. Both endpoints require a subject and authorize before reading any records or returning policies.

The public HTML and JS contain no inventory, account list, private records, credentials, or share-link tokens. Policies arrive only through the authenticated query; the page clears its DOM and in-memory data on sign-out/account changes, ignores obsolete requests, and never caches its private response in browser storage. No analytics script loads on this route. There is no public preview bypass.

Email settings are read from the current backend environment, with a separate, deny-by-default list for Standups and Monitoring. Neither tool inherits `SLEEP_ALLOWED_EMAIL`. Fixed policies and October 8 audit findings are labeled as reviewed evidence, not automatically reverified claims. The page is not a universal permission guard and does not alter any tool's permissions. Event membership and device credentials live in other deployments and are described without exporting those records. Enabled statement links are counted for the configured Payments workspace; tokens and statement contents are never returned. Counting is bounded to 501 records and labeled when capped.

Reviewed descriptions are held in private Convex configuration (`ACCESS_OVERVIEW_POLICY_PARTS` and its numbered parts). Keep the private owner policy in sync when tool policies change. Do not commit the inventory to this public repository: the private policy includes approved-account lists and dated audit evidence. Its local maintenance copy is excluded from publication, in `outputs/access-overview/owner-policy.json` under the workspace root. The endpoint reads only an explicit set of permitted access settings; it never exports arbitrary environment variables. Do not present a descriptive row as live enforcement or a passed security audit.

The October 10 permission fix restricts generic `warRoom` reads and saves to explicitly registered war rooms in both affected deployments. Monitoring, Rally, and unknown board IDs cannot use that API, even with an owner identity; their own endpoints enforce tool membership and field privacy. The October launch room keeps its existing approved accounts. Saved progress in the two June archives requires an approved owner account, and the archive pages use authenticated Clerk requests. Their static seed/reference assets remain public. Only remove the board-bypass finding from the private policy after verifying both live deployments. Downloader's browser-ID policy remains an access decision, labeled separately from a confirmed permission gap.

Missing or empty dedicated lists deny access. Standups and Monitoring each explicitly approve the two existing owner aliases; adding accounts to Sleep has no effect on either list. Monitoring machine ingestion retains its separate secrets. No tables or HTTP routes change. Preserve live modules, schema, auth configuration, cron jobs, and node dependencies when deploying; never push the stale repository backend wholesale.
