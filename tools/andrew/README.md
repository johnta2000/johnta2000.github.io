# Andrew Mission Control

Private shared project workspace at `/tools/andrew/`, listed in `/login/` after `andrew:verify` approves the signed-in account.

The latest local September–November 2026 content agreement draft supplied 14 scheduled articles with submission dates, six initially unassigned on-demand slots, 25 update slots in two batches, and hot-deal coverage. Actual article titles and source details were seeded into the private backend; no agreement records or account identities belong in public assets. The default Articles view is a seven-column spreadsheet: Article Title, Status, Office Article Link, Target submission date, Actual submission date, Notes, Feedback. Feedback supports up to 5,000 characters of multiline comments and recording links, with clickable links below the cell. Tella links show Watch Tella recording. Feedback uses the same private autosave, conflict checks, wrapping, and session recovery as notes; existing records start blank. Actual submission supports a specific date, Unknown, or N/A; existing rows default to Unknown without inferring dates from status or target dates. Notes wrap within their column and rows resize after loading, typing, font loading, or viewport resizing. Notes support multiline internal comments (up to 5,000 characters), shared only with authorized workspace members and saved when the cell loses focus. Title, notes, link and date edit inline; status is a searchable dropdown with Not Submitted, Submitted, Kitchen and Published. Updates use the same table. Historical checklist and acceptance fields are preserved without being shown. Legacy submitted/accepted rows display Submitted; publication is never inferred. Deadlines may be edited to reflect written changes.

Approved members share `andrewRecords`. A dedicated `ANDREW_PROJECT_TEAM` server setting contains members and owner roles. All reads and writes require a subject, the pinned Clerk issuer, an approved email, and no explicit failed verification claim. Every project member may change article status. Legacy company acceptance remains owner-only. The internal seed operation refuses to replace initialized records. Never expose a seed or impersonation endpoint in browser code.

Cell edits commit on change or leaving the cell; returning a field to its saved value clears the draft flag. Leaving an unfilled Specific date restores its previous Unknown/N/A selection. Actual pending or failed writes still keep the exit warning. Changes save automatically, with per-record version checks, a retry queue, conflict handling, and an unsaved-work export. Refresh loads teammate updates. Explicit sign-out confirms discarding any unsaved edits and clears private data. Session expiry hides all private rendered data but keeps the recovery copy; late responses cannot reopen the workspace. Let Clerk renew tokens normally through its cache and refresh lifecycle. Recheck backend permission silently on returning to the tab or beginning an edit after five minutes, with duplicate checks coalesced. There is no polling timer and routine checks never lock editing or show a banner. Queue writes made during verification and flush them after permission is confirmed. Lock and show a banner only on confirmed sign-out or a failed verification/save. Initial workspace loading remains gated by server authorization. A missing or rejected token while Clerk still reports an active session is unverified authentication, not confirmed expiry. Retry requests fresh credentials without ending the existing session; only explicit sign-out or Switch account calls Clerk signOut. Detect HTTP 401/403 as well as auth errors, retain in-flight writes, and revalidate saved versions before replay; conflicting recovery never overwrites teammate edits. Only unsaved edits are temporarily backed up in this tab’s sessionStorage (no tokens or credentials), bound to the server-verified account email. They survive reload in the same tab, are restored only after backend authorization for that account, and are removed after saving, confirmed discard/sign-out, or switching accounts. This is draft recovery; shared records still live in Convex. If sessionStorage is unavailable, show a warning and retain the in-memory draft for download rather than promising reload recovery. Do not add analytics to this tool.

Social accounts support Reddit and Facebook links, account notes, archive/restore, and dated manual performance check-ins. Karma/followers is a snapshot; other metrics cover the seven days ending on the observation date. Blank metrics mean unknown. Each metric delta compares the latest two check-ins. The dashboard flags check-ins older than seven days. No automatic ingestion or background monitoring is connected; a URL alone does not enable one. Account URLs and metrics remain private.

Run `node --test tools/andrew/tests/*.test.cjs login/tests/access.test.cjs`. Browser checks use synthetic identities and intercepted requests, never live mutations. They cover desktop/mobile layouts, inline edits, searchable statuses, persistence, manual social check-ins, unknown vs zero metrics, modal dismissal, save retries, conflicts and sign-out. Server tests cover access denial, owner acceptance, invalid input and concurrent writes.

Production is GitHub Pages with the existing Convex backend, not a Sites deployment. Preserve all active backend modules, auth, cron definitions and unrelated table schemas. Deploy only the bundled `andrew.ts` module and additive `andrewRecords` schema from a verified current backend snapshot. Do not deploy the entire local Convex checkout. Keep the private owner access inventory updated. Keep credentials and private seed data out of source control.

## Routes and browser history

Every section is a real link. `view=articles|updates|social` identifies the section. Article filters use `filter=scheduled|demand`, update batches use `filter=batch1|batch2`, and `q` restores search. Account and check-in editors use `edit=<record-key>`; creation uses `new=account` or `new=checkin&account=<account-key>`. Expanded social history uses `history=<account-key>` and archived accounts use `archived=1`. URLs restore after sign-in, refresh, copied links, and browser Back/Forward. Opening a route never writes records. Only navigation metadata is serialized; form drafts and private record contents are excluded. Invalid routes fall back safely, and missing records show an unavailable editor. Unsaved changes require confirmation before leaving.
