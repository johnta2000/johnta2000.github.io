# Andrew Mission Control

Private shared project workspace at `/tools/andrew/`, listed in `/login/` after `andrew:verify` approves the signed-in account.

The latest local September–November 2026 content agreement draft supplied 14 scheduled articles with submission dates, six initially unassigned on-demand slots, 25 update slots in two batches, and hot-deal coverage. Actual article titles and source details were seeded into the private backend; no agreement records or account identities belong in public assets. The default Articles view is a five-column spreadsheet: Article Title, Status, Office Article Link, Target submission date, Actual submission date. Actual submission supports a specific date, Unknown, or N/A; existing rows default to Unknown without inferring dates from status or target dates. Title, link and date edit inline; status is a searchable dropdown with Not Submitted, Submitted, Kitchen and Published. Updates use the same table. Historical checklist and acceptance fields are preserved without being shown. Legacy submitted/accepted rows display Submitted; publication is never inferred. Deadlines may be edited to reflect written changes.

Approved members share `andrewRecords`. A dedicated `ANDREW_PROJECT_TEAM` server setting contains members and owner roles. All reads and writes require a subject, the pinned Clerk issuer, an approved email, and no explicit failed verification claim. Every project member may change article status. Legacy company acceptance remains owner-only. The internal seed operation refuses to replace initialized records. Never expose a seed or impersonation endpoint in browser code.

Changes save automatically, with per-record version checks, a retry queue, conflict handling, and an unsaved-work export. Refresh loads teammate updates. Signing out clears rendered and pending private data; late responses cannot restore it. Private data is not cached in browser storage. Do not add analytics to this tool.

Social accounts support Reddit and Facebook links, account notes, archive/restore, and dated manual performance check-ins. Karma/followers is a snapshot; other metrics cover the seven days ending on the observation date. Blank metrics mean unknown. Each metric delta compares the latest two check-ins. The dashboard flags check-ins older than seven days. No automatic ingestion or background monitoring is connected; a URL alone does not enable one. Account URLs and metrics remain private.

Run `node --test tools/andrew/tests/*.test.cjs login/tests/access.test.cjs`. Browser checks use synthetic identities and intercepted requests, never live mutations. They cover desktop/mobile layouts, inline edits, searchable statuses, persistence, manual social check-ins, unknown vs zero metrics, modal dismissal, save retries, conflicts and sign-out. Server tests cover access denial, owner acceptance, invalid input and concurrent writes.

Production is GitHub Pages with the existing Convex backend, not a Sites deployment. Preserve all active backend modules, auth, cron definitions and unrelated table schemas. Deploy only the bundled `andrew.ts` module and additive `andrewRecords` schema from a verified current backend snapshot. Do not deploy the entire local Convex checkout. Keep the private owner access inventory updated. Keep credentials and private seed data out of source control.

## Routes and browser history

Every section is a real link. `view=articles|updates|social` identifies the section. Article filters use `filter=scheduled|demand`, update batches use `filter=batch1|batch2`, and `q` restores search. Account and check-in editors use `edit=<record-key>`; creation uses `new=account` or `new=checkin&account=<account-key>`. Expanded social history uses `history=<account-key>` and archived accounts use `archived=1`. URLs restore after sign-in, refresh, copied links, and browser Back/Forward. Opening a route never writes records. Only navigation metadata is serialized; form drafts and private record contents are excluded. Invalid routes fall back safely, and missing records show an unavailable editor. Unsaved changes require confirmation before leaving.
